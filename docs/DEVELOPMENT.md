# 开发流程与界面约定

基线：0.7.0 / 2026-10-25。

## 日常开发顺序

1. 读本次涉及的入口与现有测试，确认工作区已有改动；不覆盖其他未提交工作。
2. UI 工作打开 3000；美术打开 3010 的固定中性位对比。
3. 小范围修改 → 实际浏览器检查 → 保存截图或数值报告。
4. 视觉和动作分别验收；编译通过只代表工程可构建。
5. 涉及发布时再统一版本、构建、测试、打包。不要在未验收的每次绘稿后自动覆盖线上。

安装与启动见[根 README](../README.md)。浏览器测试使用 `skin-lab/node_modules/playwright` 和已安装的 Google Chrome（`channel: 'chrome'`）。

## 界面约定

当前产品方向已经明确，后续改动以此为基础：

- 白色主题、轻量卡片、粉色点缀；场景图本身可以是深色，不等于应用采用深色主题。
- 顶部左侧仅当前角色头像；右侧 FPS 与菜单。
- **顶部没有睁闭眼或额外张嘴按钮。** 口型通过下方分类操作。
- 下方四分类为表情、眼神、口型、嘴巴；可点击，也可横向滑动。
- 睁闭眼是下方操控面板右侧的独立圆按钮，不作为眼神列表的一项。
- 整个操控卡片右上角内凹挖空，露出应用背景；不是只把分类条裁掉。
- 眼睛按钮与分类条水平对齐，按钮是 `.quick-pad` 的兄弟节点，位于 `.quick-pad-shell` 内。
- 头像选择只改变使用角色；选中态、关闭按钮和两套头像应清晰一致。
- 主页面固定视口，避免整页上下滚动；分类使用横向分页，菜单使用背景/设置/保存分页。
- 不重新接回制作室、时间轴、状态参数、录制面板、底部教程提示或旧键盘编辑逻辑。

### 操控面板结构

```text
.bottom-workspace
└── .quick-pad-shell               整个操控区定位容器
    ├── .quick-pad                 真正带缺口的卡片
    │   ├── .pad-category-header
    │   │   └── .quick-pad-tabs    4 个分类
    │   └── .face-pager            横向 scroll-snap
    │       └── .face-options ×4   每页 2×4 格
    └── .pad-eye-toggle            独立圆形闭眼/睁眼按钮
```

`QuickPad.less` 同时设置了标准 `mask` 与 `-webkit-mask`。缺口中心为 `calc(100% - 24px), 34px`、半径 33px；按钮 44px、right=2px、top=12px，中心相同。改按钮位置时同步检查缺口，不要把按钮重新塞进分类条。

### 固定高度布局

`App.less` 使用固定视口 Grid：舞台占可用剩余高度，操控区占受限高度。`Stage` 通过 `.stage-viewport` 的 ResizeObserver 测量真实空间，再等比显示 800×600 舞台。

窄屏和嵌套 Grid/Flex 子项保留 `min-width:0`、`min-height:0`；否则分页内容的内在宽度会把整个页面撑开。不要只加 `overflow:hidden` 掩盖尺寸错误。

Toy 容器高度和安全区来自 CSS 变量；需同时验证浏览器视口、SDK 高度更新、横竖屏。`100dvh` 与 SDK 高度变量服务于不同运行环境。

### 表情状态

`src/constants/emotions.js` 定义按键协议和四类条目；当前控制来自虚拟按键数组。

- EyeBlink 单独切换，选择其他眼神时保留闭眼状态。
- 嘴形和嘴部风格是不同分组；切换时只清除对应分组。
- 翻页只改变操作区，不重置角色或物理状态。
- 切换角色、恢复姿态会重置相应控制/动画实例。

## 头像与表情按钮素材

源脚本：`scripts/generate-ui-faces.mjs`。需要正式开发服务运行在 3000。

```sh
node scripts/generate-ui-faces.mjs
```

输出 `public/assets/ui/`：

- 无头发的脸部缩略图：真实角色眼睛/嘴型素材合成，当前 PNG 为 288×288。
- 头像：实际头部渲染，当前 PNG 为 384×384。
- 大肥鱼头像跳过 `phoneL/phoneR` 鳍耳装饰，**仅影响头像**。
- 头像取景测量时忽略呆毛，再绘制完整头部，让多出的呆毛在头像边界被裁切，避免脸被缩小。

UI 图片链接目前附带 `?v=07`。修改同名 PNG 并发布时同步更新缓存标识，或迁移到内容哈希资源；只覆盖同名文件可能让用户继续看到旧头像。

## 按问题找文件

| 问题 | 优先检查 |
| --- | --- |
| 整页滚动 / 横向溢出 | App Grid 尺寸、安全区、子项 min-size、分页容器 |
| 缺口或圆按钮不对齐 | QuickPad JSX 的兄弟关系、mask 中心与按钮中心 |
| 角色与触摸位置不一致 | Stage 的 rect 到 800×600 映射 |
| 模糊 | 画布实际像素/DPR、图块倍率、兼容纹理；先测再改 |
| 角色比另一套更卡 | 相同设备/分辨率/输入下的实绘计数与 CPU/GL 数据 |
| 发根顶出头顶 | 整片刘海旋转是否残留、固定带实际网格行 |
| 发束出现水平切口 | SVG 闭合边、隐藏重叠、绘制顺序，不先改阻尼 |
| 只有头像大小不一致 | 头像取景规则，不改角色模型缩放 |
| 保存图像为空 | captureStage、GPU 纹理 ready、截图分辨率恢复 |

## 修改范围与生成物

- UI 修改通常不需要跑美术重建脚本。
- SVG 常规编辑修改母版，执行 `art:export`；`resources.js`、独立 SVG、锚点表属于生成物。
- 不直接手改压缩构建文件或在线服务器里的 bundle。
- 历史 `Controls`、GIF/录制等代码和依赖仍存在；是否清理应作为独立工作处理，不等于当前 UI 继续提供这些功能。
- 新增交互、修改运行入口、变更布局哲学后，同步更新本文件、根 README 与对应测试断言。
